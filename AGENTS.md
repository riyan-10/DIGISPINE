# DigiSpine working instructions

- Before starting work, read `PROJECT_NOTES.md` and `PLAN.md`.
- Keep a durable record of the user's brief, decisions, completed work, validation, unresolved questions, and next actions.
- Update `PROJECT_NOTES.md`, `PLAN.md`, and `CHANGELOG.md` after each meaningful work session. Record outcomes honestly; separate planned, implemented, and verified work.
- Treat all website copy as draft until the client supplies or approves it. Never invent clients, testimonials, business metrics, contact details, or case studies.
- Preserve the supplied brand assets in `Logos/` and the original page in `archive/original-index.html`.
- Check keyboard access, mobile layouts, reduced motion, and all four pages when changing shared navigation or interaction code.
- Do not publish publicly, push to GitHub, or connect live enquiry services unless requested.
- The existing Vercel project auto-deploys pushes to `main`. Treat a `main` push as a deployment. Keep `vercel.json` output directory aligned with the static build (`dist/`).
